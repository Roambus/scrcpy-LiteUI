# 开发

## 环境

需要 **.NET 10 SDK**（含 Windows Desktop 运行时；`dotnet --list-sdks` 能看到 10.x 即可）。
WPF 与 `net10.0-windows` 这套目标框架只在 Windows 上还原，Linux / macOS 上连 `dotnet restore` 都过不去。

```powershell
dotnet build Kuaitou.sln                 # 编译（Directory.Build.props 里开了 TreatWarningsAsErrors）
dotnet run --project src\Kuaitou.App     # 源码态直接跑界面
```

源码态用的是仓库根目录里真实的 `scrcpy\`、`icons\`、`config.json`；只有 Release 发布时才把它们
嵌进 exe（见[打包](#打包)）。

**注意**：`icons/` 目录未包含在本仓库中（原因见 [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md)）。
缺少它不影响运行与打包，只是应用列表中的图标会走降级显示。如需完整图标效果，
跑一次 `legacy\scripts\fetch_icons.py` 自动补齐（见下方[图标素材库](#图标素材库)），
或自行准备以包名命名的 `.webp` 文件放入 `icons/`。`scrcpy/` 目录已包含，无需另外下载。

## 项目结构

```
Kuaitou.sln                 解决方案（三个 src 项目 + 一个测试项目）
Directory.Build.props       跨项目统一属性：版本号、语言/Nullable、warnings-as-errors
src/
  Kuaitou.App/              WPF 界面层（唯一可执行项目）
    App.xaml(.cs)             应用入口：单实例、主题、托盘、退出收尾
    MainWindow.xaml(.cs)      主窗口外壳（侧边栏 + 右侧内容区）
    Views/                    设备主页 / 设置页 / 投屏功能栏 / 确认框
    ViewModels/               各页面视图模型（MVVM）
    Services/                 单实例、托盘、主题、投屏功能栏的窗口管理
    Themes/                   Tokens.Light / Tokens.Dark（配色）+ Controls（控件样式）
  Kuaitou.Core/             与界面无关的核心逻辑（类库）
    Storage/                  路径常量 + ADS 存储 / 配置 / 资源释放
    Adb/                      adb 调用、设备清单、输出解析
    Scrcpy/                   scrcpy 命令行构建、会话、连接/重连/音量/熄屏/解锁
    Discover/                 三级设备发现（局域网 / mDNS / 端口扫描）
    Apps/                     应用列表扫描 + 图标库匹配 / 在线抓图 / 手机取图
    Sys/                      扫码配对、诊断、日志收集、开机自启
  Kuaitou.Interop/           少量 Win32 互操作（DWM、窗口枚举、ARP 表）
tests/Kuaitou.Core.Tests/    xUnit 测试（图标匹配 / 配置合并 / adb 解析等纯逻辑）
config.json                  默认配置（Release 打包时内嵌）
appicon.ico                  应用图标
scrcpy/                      随附的 scrcpy / adb 运行时（第三方，见声明；Release 打包时内嵌）
icons/                       应用图标库（未入库；Release 打包时内嵌）
android/                     手机侧取图程序的源码与打包脚本（icondump.dex 随包分发）
scripts/check-exe-version.ps1  校验 exe 内版本号与 Directory.Build.props 一致（CI 与发版都靠它兜底）
scripts/release.ps1          一键发版：打包 → 校验 → 打标签 → 建 Release → 传资产
release_notes/               每版发布说明（入库，发版时由脚本读）
legacy/                      旧的 Python / pywebview 实现，仅作历史留存（见文末）
```

依赖方向是单向的：`Interop ← Core ← App`。`Core` 不引用任何 WPF 类型，所以能直接被
xUnit 引用测试；`App` 只负责把 `Core` 的能力接到界面上。

三级设备发现的做法与端口扫描的并发取舍（为什么压住在飞连接数、为什么用异步 socket 而不是线程池）
写在 `src/Kuaitou.Core/Discover/` 的注释里；图标匹配的多级回退链写在 `src/Kuaitou.Core/Apps/IconResolver.cs`。
这两块的取舍跟代码贴得比跟文档紧，改动时以那边为准。

## 资源与存储

单文件发布时托管程序集被压进 exe，拿不到程序集路径，据此判定「打包态」。随包资源
（`scrcpy/`、`icons/`、`config.json`、`android/icondump.dex`）以 `kres/` 为逻辑名前缀**内嵌**在程序集里，
首启由 `src/Kuaitou.Core/Storage/ResourceExtractor.cs` 解到
`%LOCALAPPDATA%\Kuaitou\runtime\<内容哈希>\`，目录里带一个完成标记，只解一次；内容变了哈希就变，
自然重新解一份。

用户状态（配置 / 应用缓存 / 日志 / 抓回的图标）仍挂在 **exe 自身的 NTFS 数据流（ADS）** 上，
和旧版一致——磁盘上不落散落文件，拷走一个 exe 就带走全部状态；所在卷不是 NTFS 时自动退回
exe 同目录的普通文件。当前实际用的是哪种方式，在「设置 → 诊断」里能看到。

## 测试与 CI

```powershell
dotnet test Kuaitou.sln                                    # 跑测试
dotnet format Kuaitou.sln --verify-no-changes               # 格式检查（只查不改）
```

测试只覆盖纯逻辑（图标匹配、配置合并、路径解析、adb 输出解析、scrcpy 命令行构建），
不碰真机也不联网，秒级跑完。CI（[.github/workflows/ci.yml](../.github/workflows/ci.yml)）
对每个提交跑三个 job，**都在 windows-latest 上**（`net10.0-windows` + WPF 在 Linux 上还原不过）：

| job | 做什么 |
| --- | --- |
| `format` | `dotnet restore` + `dotnet format --verify-no-changes`（格式不合规就红） |
| `test` | `dotnet test`（单元测试） |
| `package` | `dotnet publish -c Release -r win-x64` 真打一次包，再用 `scripts/check-exe-version.ps1` 校验产物里带的版本号与 `Directory.Build.props` 的 `<Version>` 一致 |

最后那个 job 一次验证两件事：**干净克隆（没有 `icons/`）也能打出包**；**忘了升版本号，CI 就会红**，
包发不出去。

## 打包

```powershell
dotnet publish src\Kuaitou.App -c Release -r win-x64 -o dist
```

产物是 `dist\快投.exe`，单文件自包含（`PublishSingleFile` + `IncludeNativeLibrariesForSelfExtract` +
`EnableCompressionInSingleFile`），约 80MB，**拷到任何 Windows x64 机器双击即用**，不装 .NET。

打包参数只在 `src/Kuaitou.App/Kuaitou.App.csproj` 里维护**一处**，别再从命令行手工拼参数，
否则同一份配置会变成两份，早晚各改各的漂移。

`icons/` 未入库（图标版权原因），所以从干净克隆打包时它不存在。csproj 里那条 `EmbeddedResource`
带 `Condition="Exists(...\icons)"`，缺失就跳过，**照常能打出包**——少的是内置图标素材库，
运行时仍会在线抓图、并从手机取真实图标，只是界面图标先走降级显示。想让内置素材库进包，
打包前先跑 `legacy\scripts\fetch_icons.py` 补回来。

> 内嵌资源那几条 `EmbeddedResource` **必须写 `WithCulture="false"`**：SDK 的 `AssignCulture`
> 会把逻辑名里以「文化代码」收尾的条目当成卫星程序集资源（`com.baidu.hi.webp` 的 `hi`=印地语、
> `com.lemon.lv.webp` 的 `lv`=拉脱维亚语、`notion.id.webp` 的 `id`=印尼语……），再被
> `SatelliteResourceLanguages=zh-Hans` 过滤掉，结果图标会悄无声息地少掉一批。改动这里时务必留意。

版本号在 `Directory.Build.props` 的 `<Version>`（`AssemblyVersion` / `FileVersion` 同处维护），
按改动大小走，别一路上涨：

| 位 | 什么时候动 | 例子 |
| --- | --- | --- |
| 第一位 | 大更新（大改版、不兼容的变化） | 1.x → 2.0.0 |
| 第二位 | 小更新（加功能、加选项） | 1.8.0 → 1.9.0 |
| 第三位 | 单纯修 bug | 1.8.0 → 1.8.1 |

## 发版

先写发布说明并提交（入库到 `release_notes\<tag>.md`，跟代码一起 review），然后一条命令发出去：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\release.ps1 v2.0.0 --dry-run   # 先空跑，看会发出什么
powershell -ExecutionPolicy Bypass -File scripts\release.ps1 v2.0.0             # 正式发
```

脚本依次做：核对标签版本号与 `<Version>` 一致 → 检查工作区干净 → 打包 → 校验产物 →
推送当前分支 → 打标签并推送 → 建 GitHub Release → 把 `dist\快投.exe` 以 `Kuaitou-<tag>.exe`
的名字传上去（GitHub 不支持中文资产名，会被清成 `default.exe`）。哪一步不对就停在哪一步并说明原因，
不会带病往下走。

其他开关：`-NoBuild` 用已有产物发、`-Draft` 建草稿、`-Prerelease` 标预发布、`-Force`
覆盖同名资产、`-Notes` 指定发布说明路径、`-Exe` 指定产物路径、`-Name` 指定资产名、
`-UpdateRepoMeta` 只更新仓库描述与 topics。凭据优先读环境变量 `GITHUB_TOKEN`，没有就用本机
已存的 git 凭据。

`scripts\check-exe-version.ps1` 也可以单独跑：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\check-exe-version.ps1                    # 校验默认产物
powershell -ExecutionPolicy Bypass -File scripts\check-exe-version.ps1 -Expect 9.9.9      # 走不一致分支
```

退出码：`0`=一致、`1`=不一致、`2`=打不开产物。

## 图标素材库

`icons/` 不入库，换台机器重新打包前用脚本补回来（脚本是旧的 Python 工具，归档在 `legacy/` 下）：

```powershell
.build\venv\Scripts\python.exe legacy\scripts\fetch_icons.py          # 只补缺的
.build\venv\Scripts\python.exe legacy\scripts\fetch_icons.py --slim   # 顺带统一到 128px WebP
.build\venv\Scripts\python.exe legacy\scripts\fetch_icons.py --limit 20
```

第一次用需要先建虚拟环境并装依赖：`py -3.12 -m venv .build\venv` 然后
`pip install -r legacy\requirements.txt`。

目标包名来自脚本内置的常用应用清单 + 本机 `apps_cache.json` 里真机装过的应用，
图标来源与程序运行时在线抓取用的是同一套（应用宝 → 小米商店 → iTunes）。
`--slim` 会把整个素材库统一成 128px WebP（界面里图标最大显示 48px，够 2 倍屏用），
体积大约降到原来的四成。

## 手机侧取图程序（dex）

`android/icondump.dex` 随包分发，源码在 `android/icondump/`。它只做一件事：把手机里每个
能启动的应用的图标渲染成 PNG，打成一个 zip 放在 `/data/local/tmp/`，电脑再拉回来入库。

跑法是 **dex + `app_process`**，不往手机装 App、不申请任何权限：

```powershell
adb push android/icondump.dex /data/local/tmp/kuaitou_icondump.dex
adb shell CLASSPATH=/data/local/tmp/kuaitou_icondump.dex app_process /system/bin `
  com.kuaitou.icondump.IconDump /data/local/tmp/kuaitou_icons.zip
```

进程以 shell 身份运行（uid 2000），`/data/app` 下的 base.apk 对它可读，所以能直接解出
别的应用的图标资源。全程没有界面，也不会像装 App 那样在手机上留下东西——导出和拉取都完事
后电脑会把推上去的 dex 和 zip 删掉。

这条路踩过的坑（`app_process` 里起不了应用上下文得走 `ServiceManager` 反射、
`getInstalledPackages` 返回的是 `ParceledListSlice` 少调一次 `getList()` 就会抛
`ClassCastException`、自适应图标为什么要补圆角裁剪且不能再放大）都写在
`android/icondump/src/com/kuaitou/icondump/IconDump.java` 的注释里，改动前先读那里。

改了源码后用 `android/build.ps1` 重新打包。它不走 Gradle（这个程序没有资源文件、没有第三方
依赖），直接 javac → d8 两步出产物：

```powershell
powershell -ExecutionPolicy Bypass -File android\build.ps1
```

需要 JDK 17 与 Android SDK 的 build-tools 35.0.1、platform android-35，放成这样即可：

```
.build/toolchain/jdk-17.0.20.1+1
.build/toolchain/sdk/build-tools/35.0.1
.build/toolchain/sdk/platforms/android-35/android.jar
```

## legacy/

`legacy/` 是旧的 Python / pywebview 实现（v1.9.0 及以前），只为保留历史与「当初怎么做的」的
可追溯性，**不参与构建、不进 CI、也不进发布产物**。用 C# 重写时把功能与取舍逐条对照过来，
实现细节以 `src/` 为准。

里面唯一还在用的是 `legacy\scripts\fetch_icons.py`（图标素材库维护脚本，见上）。
